# 医療材料売上検索システム

Excelの医療材料実績をブラウザ内で読み込んで検索する静的Webアプリです。HTML、CSS、JavaScript、SheetJS（xlsx.js）で構成し、フレームワーク、バックエンド、データベースは使用しません。

## フォルダ構成

```text
medical-sales-search/
├── index.html   画面、集計対象の選択、通信制限（CSP）
├── style.css    レスポンシブ表示、自動ダークモード
├── app.js       Excel読込、検索、施設数計算、CSV出力
└── README.md    セットアップと公開手順
```

## セットアップ

1. このフォルダをPCに保存します。
2. `index.html` をブラウザで開きます。
3. インターネット接続がある状態で、画面の「Excelファイルを選択」から `.xlsx` または `.xls` を選びます。
4. 集計対象を選び、検索条件を入力して「検索」を押します。

ブラウザの制限でファイルを読めない場合は、VS CodeのLive Server拡張機能などでローカル表示してください。公開時はGitHub PagesのURLを利用します。SheetJSを公式CDNから読み込むため、初回表示にはインターネット接続が必要です。組織のポリシーでCDN利用が禁止される場合は、公式配布ファイルをこのフォルダに同梱し、`index.html` のscript参照とCSPの許可先をローカルに変更してください。

## GitHub Pagesで公開する手順

1. GitHubで空のリポジトリを作成します。Excelファイルはリポジトリに追加しないでください。
2. このフォルダ内の `index.html`、`style.css`、`app.js`、`README.md` をリポジトリのルートへアップロードします。空のリポジトリの場合は、中央のQuick setupにある「upload an existing file」リンクを使えます。
3. リポジトリの **Settings → Pages** を開きます。
4. **Deploy from a branch** を選び、ブランチ `main`、フォルダ `/ (root)` を指定して保存します。
5. Pagesに表示されたURLを開き、Excel読込と検索を確認します。

リポジトリをPublicにすると、アプリのコードは誰でも見られます。利用者が選ぶExcelデータはPagesにもGitHubにもアップロードされません。

## 集計対象と施設数

「施設ごとの集計対象」で次のいずれかを選べます。

- **施設と支店の合算**：各施設の「施設」列と「支店」列を足します。
- **施設のみ**：「施設」列だけを使います。
- **支店のみ**：「支店」列だけを使います。

どのモードでも、同じ施設の「施設」列と「支店」列は一組として扱います。Excel内に施設列が横方向に追加されていても、列見出しから施設を自動検出し、結果テーブルにすべて横並びで表示します。「使用施設数」は、選択中の対象に数量がある各施設を1回ずつ数えます。同じ施設の施設列と支店列の両方に数量があっても、合算モードでは1施設です。モードを変更すると合計、施設数、検索結果、ランキング、発注数量を選択対象に合わせて再計算します。

「施設と支店の合算」では、元データの「全施設合計」を月平均出荷数として使います。除外した施設の月平均を差し引きます。「施設のみ」「支店のみ」では、該当する各施設列を合計します。施設列の見出しは末尾の「(施設)」「(支店)」で判別し、その前にある名前を施設名として使います。施設列が横方向に増えていても自動検出します。

## 発注数量

発注日数（初期値10日）と計算対象の施設を指定できます。全施設を選択した状態で読み込み、チェックを外すとその施設を計算対象から除きます。

```text
対象月平均出荷数 = 全施設合計 − 除外施設の月平均出荷数
発注数 = 対象月平均出荷数 × 発注日数 ÷ 30 を切り上げ
```

施設のみ／支店のみモードでは、各施設の対応する列を合計して対象月平均出荷数を出します。発注施設は、計算対象に含まれ販売数がある施設のうち、月平均出荷数が最も多い施設を自動で選びます。検索結果表には対象月平均出荷数、発注数、発注施設を表示します。発注CSVは見本に合わせて「商品コード、商品名、規格、製品番号、メーカー名、発注数、発注施設」の7列を出力し、発注数が1以上の商品だけを含めます。在庫数、発注ロット、納期、安全在庫は計算に含みません。

## 検索機能

- 商品コード、商品名、メーカー名の部分一致
- Excelから読み込んだ全施設の絞り込み、施設別の上位表示
- 選択対象に基づく使用施設数の条件
- 施設別・全施設合計の数量条件とランキング
- 指定日数分の発注数量計算と施設の除外
- 発注CSV（商品コード、商品名、規格、製品番号、メーカー名、発注数、発注施設）
- PC・スマートフォン対応、自動ダークモード

検索例：`A000001`、`人工透析回路`、`施設Aのニプロ製品`、`施設Bで月10個以上使用される商品`、`使用施設数が3以上の商品`、`施設Dの上位商品`、`全施設合計トップ20`。

自然文検索はJavaScriptのルールベースです。読み込んだ列見出しと一致する施設名を条件に指定できます。既定の上位件数は10件です。

## セキュリティ設計

- ファイルはブラウザのFile APIで読み、ブラウザ内メモリでのみ処理します。
- ファイルや検索データのアップロード、外部送信、ログ出力はしません。アプリで `fetch`、XHR、WebSocketを使用しません。CSPの `connect-src 'none'` でも通信を禁止しています。
- localStorage、sessionStorage、IndexedDB、Cookieへデータを保存しません。
- 読込上限は25 MBです。セル表示には `textContent` を使い、CSV出力時には数式として解釈される可能性がある文字列を保護します。
- 「データをクリア」またはページの再読み込み・終了で、アプリ内のデータ参照を破棄します。

CDNからSheetJSのコードを取得するため、利用者のブラウザはその配布元へ接続します。Excelの内容は送信しません。機密データを扱う組織では、公式配布物を確認して同梱する運用を検討してください。

## Azure OpenAIへの拡張ポイント

自然文から検索条件を作る処理は `parseQuery()` です。将来モデルを接続する場合、この部分を構造化条件へ変換する処理に置き換え、データ照合自体は `matches()` とブラウザ内レコードに対して実行できます。

Azure OpenAIへ質問を送ると、その質問文は外部サービスに送信されます。Excelの行データをモデルへ送らない設計にし、GitHub PagesのJavaScriptへAPIキーを埋め込まないでください。外部送信を避ける要件を維持する場合は、ルールベース検索を拡張します。
