# 医療材料売上検索システム

Excelの売上実績をブラウザ内で読み込み、ルールベースの自然文検索を行う静的Webアプリです。React、Vue、Angular、TypeScript、Node.js、バックエンド、データベースは使いません。

## フォルダ構成

```text
medical-sales-search/
├── index.html   画面とCSP（Content Security Policy）
├── style.css    レスポンシブ表示、ライト／ダーク配色
├── app.js       Excel読込、条件解析、検索、CSV出力
└── README.md    セットアップと公開手順
```

## セットアップ

1. このフォルダをPCに保存します。
2. `index.html` をブラウザで開きます。
3. インターネット接続がある状態で、画面の「Excelファイルを選択」から `.xlsx` または `.xls` を選びます。
4. 質問欄に検索条件を入力して「検索」を押します。

ブラウザによっては `file://` からの実行が制限されることがあります。その場合は、フォルダをVS Codeで開き、Live Server拡張機能で `index.html` を表示してください。Live ServerはローカルPC内だけで動作する開発用サーバーです。公開時はGitHub PagesのURLを使います。

アプリはSheetJSのブラウザー用ファイルを公式CDNから読み込みます。Excelファイルの読込・解析・検索はブラウザ内で完了します。検索データを送信するコードはなく、CSPの `connect-src 'none'` でアプリからの通信も禁止しています。CDNからライブラリを読み込むため、初回表示にはインターネット接続が必要です。組織ポリシーでCDN利用が禁止される場合は、公式ライブラリファイルを同じフォルダに配置し、`index.html` のCDN参照とCSPの許可先を `'self'` に変更してください。固定バージョンを使用し、配布前に組織のソフトウェア確認手順に従ってください。

## GitHub Pagesで公開

1. GitHubで新しい空のリポジトリを作成します。機密情報を含むExcelファイルをリポジトリへ追加しないでください。
2. このフォルダ内の `index.html`、`style.css`、`app.js`、`README.md` をリポジトリのルートに配置します。
3. GitHubリポジトリの **Settings → Pages** を開きます。
4. **Build and deployment** の **Deploy from a branch** を選び、公開するブランチ（例：`main`）と `/ (root)` を指定して保存します。
5. 表示されたPagesのURLを開き、Excel読込と検索が動作することを確認します。

この構成はビルド不要です。Pagesへ公開されるのはアプリのコードだけで、利用者が選択したExcelデータは公開対象にもGitHubにも送られません。公開URLは誰でも閲覧できます。利用者が選択したファイルはブラウザのメモリ上だけにあり、ページ再読込または「データをクリア」で破棄されます。

## 検索機能

- 商品コード、商品名、メーカー名の部分一致
- 施設A〜Eで使用されている商品の絞り込み
- 各施設の「施設」列と「支店」列を合算した最低使用数の条件
- 使用施設数の最低値条件
- 全施設合計または施設別の上位N件（既定10件）
- 検索結果のCSVダウンロード（該当する全商品）
- モバイル／PC表示、自動ダークモード

検索例：

```text
A000001
人工透析回路
施設Aのニプロ製品
施設Bで月10個以上使用される商品
使用施設数が3以上の商品
施設Cでよく使われる商品
施設Dの上位商品
全施設合計トップ20
```

自然文検索はAIではなく、`app.js` 内のパターン解析です。施設名は施設A〜Eを想定します。施設名と数量がある条件では、その施設の施設列と支店列の合算値を比較します。施設名がない数量条件は「全施設合計」で判定します。施設別の使用量が元データ上の全施設合計と一致するかは、元ファイル側の集計方法に依存します。

## セキュリティ上の設計

- ファイル選択後にブラウザの `File.arrayBuffer()` で読むため、ファイルパスをサーバーへ渡しません。
- Excel内容を外部通信、アップロード、ログ出力しません。`fetch`、XHR、WebSocketは使用していません。
- `localStorage`、`sessionStorage`、IndexedDB、Cookieへデータを保存しません。
- Excel読込は25 MBまでに制限し、見出し行と必須列を検証します。
- セルの表示にはDOMの `textContent` を使い、Excel内の値をHTMLとして解釈しません。
- CSVは利用者が明示的に押したときにだけ作成してダウンロードします。
- 読み込んだデータはメモリ内の変数に保持し、「データをクリア」またはページを閉じると参照を破棄します。

ブラウザでHTMLを実行するため、外部ライブラリの配布元を信頼する必要があります。特に機密データを扱う組織では、公式配布物を確認して同梱し、CDNなしで運用してください。Excelファイルの解析結果を画面に表示するため、画面共有や端末管理など利用者側の情報管理も必要です。

## Azure OpenAIへの将来拡張ポイント

現在の検索は `parseQuery()` が自然文を検索条件へ変換し、`search()` と `recordMatches()` がブラウザ内データに適用します。Azure OpenAIを追加する場合は、自然文を構造化条件へ変換する部分を置き換え、結果の絞り込みは引き続きブラウザ内で行う構成が考えられます。

ただし、Azure OpenAIへ質問を送ると、その質問文やそこに含まれた情報は外部サービスへ送信されます。Excel行データや商品情報をモデルへ渡さず、必要な場合に利用者へ明確に知らせる設計にしてください。Azureのキーを静的なGitHub PagesのJavaScriptに埋め込むのは避けてください。認証情報が必要な構成では、Azure側の安全な認証基盤や薄いAPIを別途用意し、送信する内容・ログ・保持期間・アクセス制御を組織のポリシーに合わせる必要があります。外部接続を行わない要件を維持するなら、ルールベース検索を拡張してください。
